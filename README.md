# Marketplace — Telegram Mini App

Полный проект на Next.js 14, React и TypeScript: интерфейс маркетплейса, выдвижная панель админки, магазины, баннеры, FAQ, верификация, жалобы и журнал действий.

## Что изменено в этой версии

Подробный список изменений v8 см. в `CHANGELOG-v8.md`.

- Права владельца закреплены за Telegram ID `998579758`. Остальные пользователи по умолчанию получают роль участника; роли сотрудников и магазинов читаются из серверной базы, а не из клиентского `localStorage`.
- Добавлена серверная проверка подписи Telegram Web App `initData` по `TELEGRAM_BOT_TOKEN`.
- Добавлен слой API для управления ролями, баннерами, магазинами, FAQ, верификацией, жалобами, решениями и банами.
- Добавлено хранение записей и аудита в Supabase, серверная загрузка фото через Storage и публичные ссылки на изображения.
- URL баннеров проверяются как полные `http://` / `https://` адреса, поэтому адрес сайта Marketplace к ним не дописывается.
- Баннеры и магазины выводят дату создания; в обзоре админки есть действия скрытия, восстановления и удаления.
- Жалобы хранят название объекта, отправителя, сведения о владельце и ссылки на доказательства; модератор может закрепить дело за собой, а владелец/заместитель — принять окончательное решение.

## Настройка серверной базы

1. Откройте ваш проект Supabase (`mcrlvlxuyygimlgkbzvk`).
2. В SQL Editor выполните файл `supabase/schema.sql` один раз, чтобы создать таблицы и Storage bucket.
3. В Vercel откройте **Project → Settings → Environment Variables** и добавьте переменные для Production (а также Preview, если нужна тестовая среда):
   - `NEXT_PUBLIC_SUPABASE_URL` — `https://mcrlvlxuyygimlgkbzvk.supabase.co` (публичный URL проекта).
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` — ваш ключ `sb_publishable_...`. Он публичный; текущие серверные API используют service role key, поэтому publishable key не заменяет серверный ключ.
   - `SUPABASE_URL` — тот же URL проекта. Сервер умеет использовать `NEXT_PUBLIC_SUPABASE_URL` как запасной источник URL.
   - `SUPABASE_SERVICE_ROLE_KEY` — секретный серверный ключ из Supabase **Settings → API Keys**. Берите секретный/service role key (не publishable), добавляйте его только в Vercel и локальный `.env.local`; **никогда не помещайте его в `NEXT_PUBLIC_*`, Git или сообщения чата**.
   - `TELEGRAM_BOT_TOKEN` — токен Telegram-бота из BotFather. Он нужен серверу для проверки Telegram Web App `initData`; его также нельзя публиковать.
   - `TELEGRAM_BOT_USERNAME` и `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME` — имя бота без `@`, чтобы формировать одинаковую персональную ссылку из профиля и бота.
   - `TELEGRAM_WEBHOOK_SECRET` — длинный случайный секрет для проверки запросов от Telegram webhook.
   - `NEXT_PUBLIC_APP_URL` и `APP_URL` — канонический URL Mini App (лучше свой домен, без Vercel URL).
4. После сохранения переменных запустите новый Redeploy в Vercel, иначе существующий deployment не подхватит новые значения.
5. Убедитесь, что Mini App запущен через Telegram Web App, чтобы в запросах присутствовал `initData`.
6. Установите зависимости и проверьте сборку:

```bash
npm install
npm run build
npm run dev
```

Важное различие: серверные API этого проекта используют `SUPABASE_SERVICE_ROLE_KEY` для серверного доступа и поэтому не используют publishable key для административных операций. Не подставляйте publishable key вместо service role key — при включённом RLS операции не получат нужных прав.

## Важно перед публикацией

- Объявления, отзывы, подписки профилей, подписки магазинов, уведомления, роли, жалобы и настройки витрин сохраняются в Supabase. Избранное, история просмотров и некоторые не критичные UI-настройки остаются локальными для браузера.
- Предупреждения записываются как внутренние уведомления в Supabase. Отправка настоящих сообщений пользователю через Telegram Bot API требует, чтобы пользователь ранее открыл бота и чтобы был подключён соответствующий отправитель уведомлений.
- Администратор должен назначать магазин пользователю по его Telegram ID (или username, если пользователь уже запускал приложение); магазинный владелец не получает доступ лишь от имени/username в браузере.
- Верификация доступна после того, как пользователь хотя бы один раз вошёл в Mini App и его Telegram ID появился в БД.
- Полная сборка в рабочем окружении при подготовке архива не была подтверждена: npm registry был недоступен (`EAI_AGAIN`). Обязательно запустите `npm install` и `npm run build` перед деплоем и проверьте вывод Vercel.

## Подключение Telegram-бота

1. В BotFather возьмите `TELEGRAM_BOT_TOKEN`, укажите username бота в `TELEGRAM_BOT_USERNAME` и `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME`.
2. Установите `TELEGRAM_WEBHOOK_SECRET` как длинную случайную строку. После деплоя задайте webhook, передавая секрет заголовком `secret_token` (не добавляйте токен бота или секрет в клиентский код):

```bash
curl -X POST "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/setWebhook" \
  -d "url=${NEXT_PUBLIC_APP_URL}/api/telegram/bot" \
  -d "secret_token=${TELEGRAM_WEBHOOK_SECRET}" \
  -d 'allowed_updates=["message"]'
```

3. Проверьте в личном чате бота `/start`, `/ref`, `/shops`, `/subscriptions`, `/moderators`, `/stats` и `/complaint`. Персональные рефералы засчитываются при первом `/start` с параметром `?start=<Telegram ID>`; простое открытие сайта не считается.
4. Объявления администрации запускаются из админ-панели и доставляются в приложении всем зарегистрированным пользователям, а через Telegram — только тем, кто уже запускал бота.
