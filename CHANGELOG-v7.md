# Marketplace — изменения v7

- Добавлен раздел «Пользователи» в админ-панели: серверный поиск по Telegram ID, username и имени; отображение статуса блокировки, профиля и доступной статистики; снятие активных банов; назначение временной или постоянной блокировки.
- Поиск пользователей разрешён только административным ролям, блокировку и снятие ограничений сервер проверяет по роли владельца/заместителя.
- Жалобы открывают подробную информацию об объекте и материалах; добавлена ссылка на объявление, если объект доступен в текущем каталоге. Владелец/заместитель сохраняет возможность вынести окончательное решение независимо от того, взял ли дело модератор.
- Убраны заранее заданные тестовые объявления, магазины, жалобы и отзывы; при восстановлении старого localStorage фильтруются известные тестовые записи.
- Логотип магазина используется как фоновое изображение всей карточки витрины.
- Добавлено ручное изменение порядка магазинов и перемешивание; порядок серверных магазинов сохраняется через API в `marketplace_shops.display_order`.
- Добавлена серверная регистрация просмотров только после проверки подписи Telegram. Один Telegram-аккаунт учитывается не более одного раза на объявление.
- Добавлены реферальная атрибуция проверенных Telegram-аккаунтов (`referred_by`) и счётчик приглашённых аккаунтов. Ссылка использует текущий домен сайта; чтобы скрыть домен Vercel, настройте собственный домен в Vercel.
- FAQ поддерживает новые пользовательские разделы: раздел создаётся вводом нового имени в поле «Раздел», а опубликованные разделы выводятся отдельными блоками.
- Для баннеров указана рекомендуемая панорамная пропорция 1600×600 (8:3) и предупреждение об обрезке фото 16:9.

## Требует внимания

- После обновления необходимо выполнить обновлённый `supabase/schema.sql` в Supabase SQL Editor (он добавляет `marketplace_listing_views`, `referred_by`, `referral_attributed_at` и `display_order`).
- Счётчик просмотров считает уникальные подтверждённые Telegram ID для каждого `listing_id`, но объявления как полноценная серверная сущность ещё не перенесены в таблицу; текущие ID объявлений генерируются интерфейсом. Для кросс-устройственной статистики объявлений нужен отдельный перенос объявлений в Supabase.
- Счётчик referral засчитывает только пользователя, чья подпись Telegram проверена сервером и который уже существует в `marketplace_users`. Сам переход по ссылке не считается регистрацией.
- Не удалось подтвердить `next build` в среде подготовки: зависимости Next.js/React отсутствуют, npm registry недоступен. Требуется повторная сборка в Vercel.
